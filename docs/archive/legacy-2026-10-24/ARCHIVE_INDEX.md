## Retention policy and provenance

- `main/`: all documentation and reference assets from the original main baseline, plus its README, AGENTS, LICENSE, TRADEMARKS and release notes.
- `branch-variants/<branch>/`: every documentation/reference file present at that branch tip whose blob differs from the original main baseline, including branch-only files. Unchanged documents are represented by `main/`. Files absent from a branch are not invented; consult its full tagged tree for exact structure.
- Every pre-existing archived file has been retained byte-for-byte. All copied files reuse the exact original Git blob; historical status is supplied by this index rather than altering source text or legal notices.
- The table below lists every copied file, its original path and immutable commit URL. Large historical reference assets are copied too; no file in this table is merely a link represented as a copy.
- Application source, tests, migrations, workflows, scripts and dependency files outside these retained references are **historical-reference only through the full snapshots above**, not duplicated here. Their exact immutable paths are under each linked commit tree.
- GitHub archival pre-releases accompany these tags solely because GitHub's web release UI was used to create them. They are recovery markers, not new application releases. Existing `v0.2.0` is retained.
