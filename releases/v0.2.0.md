## Increment 1 scope

`v0.2.0` is limited to the first usable Dotick product vertical slice:

- Identity and account foundation;
- Folder/List/Column organization;
- Item identity/ownership/source foundation required by the slice;
- unscheduled Basic Task MVP;
- web/Android Expo client flows required to exercise the slice.

## Delivered functionality

### Identity and account

- Email/password registration and sign-in.
- Email verification and verification resend.
- Password-reset request and confirmation.
- Argon2 password hashing and case-insensitive email identity.
- Rotating/revocable JWT sessions, session listing/revocation and recent-authentication boundaries.
- Google identity sign-in/linking boundary with password fallback.
- WebAuthn Passkey registration/authentication boundary with password fallback.
- Account profile, handle/display-name/profile-picture reference and IANA timezone foundation.
- Verified secondary-contact APIs.
- Environment-driven email/SMS, Google and WebAuthn provider configuration with clean unavailable/unconfigured behavior.

### Folder / List / Column

- Idempotent account bootstrap that creates UserPreferences and exactly one Inbox.
- Exactly one default Column per List, including the Inbox.
- UUID-based owner-scoped Folder/List/Column persistence with ordering, timestamps and recoverable Trash/restore behavior.
- Atomic List/default-Column creation.
- Stable versions, stale-write rejection and retry-safe operation IDs at current I1 mutation boundaries.
- No separate `Tab` or `Section` entities.
- The legacy technical default-Column name is not exposed as the user-facing label when it is the only Column.

### Basic Task MVP

- Explicit Item/Task persistence with stable UUID identity.
- Owner, creator and source/provenance foundation.
- Unscheduled Task create/read/edit.
- Todo, Done and Won't_Do status transitions in the I1 boundary.
- Placement in Inbox/List/Column and movement between loaded Columns.
- Recoverable Task Trash/restore.
- Optimistic versions, stale-write protection and retry-safe create semantics.
- Owner-scoped access and cross-account isolation.

### Client and integration

- I1 product workspace replaces the Increment 0 Checkpoint workbench as the visible product client.
- Registration, verification/resend, password reset and password sign-in flows.
- Configured web Google and Passkey sign-in entry points.
- Bootstrap, Inbox/List navigation, List creation and Basic Task create/edit/status/move/Trash/restore flows.
- In-memory session handling, refresh rotation and private-state cleanup on sign-out.
- Conflict recovery that refreshes server-authoritative state instead of silently overwriting it.
- Failed-save draft preservation.
- Desktop and mobile-viewport Playwright coverage of the real client → Django API → PostgreSQL I1 path.

### Engineering and verification assets

- OpenAPI 3.1 contract with route/authentication compatibility checks.
- Append-only migrations, migration-history/drift checks and fresh-database reconstruction tooling.
- Backend, client unit/component/network and compatibility tests.
- Ruff, TypeScript, ESLint and Prettier checks.
- Expo web export.
- Desktop/mobile Playwright projects.
- API/web container builds, smoke checks and restart-persistence infrastructure.
- Python/npm dependency audits and repository secret scanning.

## Explicit exclusions

The following are not part of Increment 1 and are not introduced by `v0.2.0`:

- Event and complete schedulable Task behavior;
- Task hierarchy/dependencies, RichDescription, comments and Audit foundation owned by later increments;
- Routine/RoutineCompletion;
- recurrence, reminders and full time/calendar behavior;
- complete navigation/view/theme scope;
- full offline-first Sync, branching History and Undo;
- sharing, groups, assignment and realtime collaboration;
- AI-assisted creation, Goals, AI tags/discovery, Daily Rings, scoring and statistics;
- production-readiness capabilities owned by Increment 11;
- permanent Trash purge semantics;
- full Folder/custom-Column management UI, Passkey enrollment UI, Google linking UI, or full profile/contact/session management UI where the I1 implementation remains API-first;
- provider-specific native Google/Passkey behavior.

## Verification and binding

`v0.2.0` is bound only after:

- exact-commit local verification of backend/frontend suites, desktop/mobile I1 E2E, fresh migrations, production settings, Docker persistence, dependency/security scans and secret checks;

External email/SMS delivery is optional and unconfigured by default. Real Google/WebAuthn, authenticator, edge and production-device verification remains explicit Increment 11 deployment work and is not claimed by this release.
